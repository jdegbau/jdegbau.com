## What is a Sankey chart?

A Sankey chart (also called a Sankey diagram) has two parts:

- **Nodes** are the bars. Each one is a group or a stage, such as a traffic source, a page, or an outcome. Its height is its total.
- **Bands** (also called links or flows) connect the nodes. A band's width is the amount moving from one node to the next.

Nothing is lost or invented between stages. What flows into a node equals what flows out of it, so the totals reconcile from left to right. That rule is what makes a Sankey chart trustworthy, and it's the first thing to check when one looks wrong.

The chart is named after Matthew Henry Phineas Riall Sankey, an engineer who used one in 1898 to show how much of a steam engine's energy became useful work and how much was lost as heat.

## Why and when to use a Sankey chart

A table lists the numbers. A Sankey chart shows **where they go**. Reports often split one journey across three disconnected tables (traffic by channel, visits by landing page, conversions by page). A Sankey puts the whole path in one view, so the reader sees the connections instead of rebuilding them.

Use a Sankey chart to show:

- **How a total splits** into paths, such as visits by source and landing page, or a budget by team and project.
- **What survives** each stage of a process, such as leads becoming opportunities and then customers.
- **Where things get lost** along the way, so the biggest leak is the widest band heading to "Left."

It works best with two to four stages and a handful of nodes in each. For more chart types and when each one fits, see the [SEO data visualization guide](/blog/seo-data-visualization-guide/).

## How to read a Sankey chart

Read it in four steps, left to right.

<Steps label="How to read a Sankey chart">

1. **Start on the left.** Each node is a source, sized by its total. Search is the biggest at 520 visits, more than half the total.
2. **Follow the widest band.** Width is quantity, so the widest band is the biggest flow. Here it's the 400 visitors who landed on the Blog and left.
3. **Compare what goes in with what comes out.** Pricing gets 260 visitors, fewer than the Blog's 460, but 140 of them sign up. That's 54%, against 13% for the Blog and 18% for Home.
4. **Finish on the right.** The outcome nodes add up to the total: 250 signed up and 750 left.

</Steps>

The takeaway writes itself: Pricing is the best-converting page, so sending more of the Blog's 460 visitors there (with links or calls to action) is likely worth more than growing Blog traffic further. That's the kind of decision a Sankey chart supports and three separate tables hide.

<Callout type="tip" title="Check the totals">

Add up each column of nodes. If they don't match (say, 1,000 visits on the left and 1,080 on the right), the data mixes units, like sessions and users, or counts some visits twice. Fix that before you share the chart.

</Callout>

## Other mistakes to avoid

- **A different color for every flow.** Color should carry meaning. Use one neutral color, and save a bright one for the flow you want people to notice.
- **Dozens of thin bands nobody can follow.** Group small sources into an "Other" node. Four referral sources of 21 visits each say more as one "Other · 84" node.
- **Nodes in random order, so bands cross.** Order nodes so the biggest flows run as straight as possible. Crossings make readers trace bands by hand.
- **Totals that don't reconcile.** Every stage should add up to the same total. If it doesn't, the chart is wrong, not just ugly.
- **No numbers on the nodes.** Widths show proportion, not value. Add the total to each node's label, as in the example above.

## When not to use a Sankey chart

A Sankey chart is the wrong choice when:

- **Flows loop back.** If items return to an earlier stage (visitors going back and forth between pages), use a network diagram or a path analysis instead.
- **There's only one path.** If everyone moves through the same steps in order, a funnel chart is simpler.
- **Exact values matter.** Readers judge width poorly. If they need to compare 140 with 120, use a table or a bar chart.
- **You need to show change over time.** A Sankey is a snapshot. Use a line chart for trends.
- **You have more than about eight nodes per column.** It turns into spaghetti. Split it into two charts or group the small nodes.

## How to make a Sankey chart

Every Sankey tool needs the same table with three columns: where the flow starts, where it ends, and how much moves. That's the format of the example dataset.

<TabPanel label="SankeyMATIC">

[SankeyMATIC](https://sankeymatic.com/build/) is free and runs in the browser. Type one flow per line, with the amount in brackets, and the chart draws as you type:

```text
Search [320] Blog
Search [120] Pricing
Search [80] Home
Pricing [140] Signed up
Pricing [120] Left
```

</TabPanel>
<TabPanel label="Flourish or RAWGraphs">

Both are free, no-code tools. Paste the three columns into a new Sankey chart (Flourish) or a Sankey diagram (RAWGraphs), map the columns to source, target, and value, and export an image or embed code.

</TabPanel>
<TabPanel label="Python">

Plotly's `Sankey` takes node labels plus three lists for the links: source and target (as positions in the label list) and value.

```python
import pandas as pd
import plotly.graph_objects as go

df = pd.read_csv("sankey-example-visitors.csv")
labels = list(dict.fromkeys(df["from"].tolist() + df["to"].tolist()))
index = {label: i for i, label in enumerate(labels)}

fig = go.Figure(go.Sankey(
    node=dict(label=labels),
    link=dict(
        source=df["from"].map(index),
        target=df["to"].map(index),
        value=df["visitors"],
    ),
))
fig.show()
```

</TabPanel>

## Recap

- A Sankey chart shows how a **total flows** between stages.
- **Band width** is quantity, and every stage adds up to the same total.
- Read it **left to right**: sources, paths, outcomes.
- Keep it to **a few flows** and one highlight, and add the totals to the node labels.
- Use a funnel for a single path, a table for exact values, and a line chart for trends.
